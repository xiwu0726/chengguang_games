# 出图流水线（正式美术替换占位图）

目标：把 `Assets/Resources/Art/{Bg,Cg,Portrait}/` 里 104 张程序渐变占位图（图上烙有文件名白字）替换为正式美术。**当前唯一缺口：一个图像生成 API key，或外部画师按 `art/manifest.json` 交付 PNG。**

## 1. 现在缺什么

- **2026-10-16 实测：本机四条图像通道全空** —— `generate_image` 报缺 Google Gemini API key；`provider=openai` 同样缺 key；三个订阅通道（Google / ChatGPT / Grok）都返回「未登录：请到 设置 > 插件 > 图像生成 的订阅区完成登录」。环境变量里也没有任何图像 key（`GOOGLE_GEMINI_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY` / `ARK_API_KEY` / `ZHIPU_API_KEY` / `XAI_API_KEY` / `DASHSCOPE_API_KEY` 全部为空），本机也没有在跑的 ComfyUI / SD WebUI（127.0.0.1:8188 / 7860 / 1234 都不通）。**所以正式美术目前一张也出不了，需要先补下面任一条。**
- 拿到 key 后设两个环境变量即可真实出图（key 只走环境变量，工具不硬编码、不打印、不落盘）：
  - `DSH_IMAGE_PROVIDER` = `google` 或 `openai`
  - `GOOGLE_GEMINI_API_KEY`（provider=google 时）或 `OPENAI_API_KEY`（provider=openai 时）
  - 可选 `DSH_IMAGE_MODEL` 覆盖默认模型（google 默认 `gemini-2.0-flash-preview-image-generation`，openai 默认 `gpt-image-1`）。
- 走 DSH 的订阅通道（`generate_image` 的 `provider=chatgpt-sub|grok-sub|google-sub`）只需在 设置 > 插件 > 图像生成 里登录一次，不单独付 API 费；但这条路径由助手逐张驱动，`gen-art.js` 的批量后处理（裁切/抠底）仍要配合 `art-review.py` 使用。
- 走外部画师：把 `art/manifest.json` 的 `prompt`/`negative`/`size` 字段直接发给画师，交付 `<id>.png` 即可，命名与尺寸红线见第 4 节，验收用第 3 节的审图表命令。

## 2. manifest 结构（art/manifest.json）

- 104 条 = 剧本实际引用 86 条（`"used": true`，bg 22 / cg 33 / 立绘 31）+ ASSETS.md 登记但剧本未引用的 18 条备用（`"used": false`）。
- 每条含 `id / kind / used / refCount / target / size / title / style / prompt / negative / palette / source / notes`；立绘另有 `character / transparent / consistency / identitySource`。
- `source` 指向简报真实文件与行号；为空的 6 条是补写的表情变体（notes 已说明）。指南里可直接复用的 prompt：立绘 38 条、场景 16 条（已全部吸收进 manifest；指南无 CG prompt，42 张 CG 均为按 ASSETS 用途 + BIBLE 结局表补写）。
- 立绘一致性规则：每个角色先出基准图（`linxiao_normal / alice_calm / raine_alert / xya_smile / lord_calm / zhou_kind / vera_cold`），其余表情变体**必须以基准图为参考图**生成，保持同一张脸、发型发色、瞳色、服装，只改表情视线。`gen-art.js --generate` 已按此顺序自动传参考图（openai 走 images/edits，google 走 inlineData 参考）。

## 3. 命令

**逐组跑（推荐）**：一条命令按顺序出「场景底图 → 七个角色立绘 → CG」，每组出完自动生成一张带 id 标注的审图表。

```powershell
# 先不联网验证分组与命令是否正确（9 组全 OK 再进下一步）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\art-batch.ps1 -DryRun

# 真实出图（需先在环境变量里给 key，脚本只读环境变量、不写仓库、不打印值）
$env:DSH_IMAGE_PROVIDER = "google"          # 或 "openai"
$env:GOOGLE_GEMINI_API_KEY = "<你的 key>"    # provider=google 时
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\art-batch.ps1

# 只跑其中几组（审图不过关时单独返工最省额度）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\art-batch.ps1 -Groups alice,cg
```

- 默认分组顺序：`bg -> linxiao -> alice -> raine -> xya -> lord -> zhou -> vera -> cg`（立绘按引用次数从多到少，基准图先出、表情变体自动带基准图作参考）。
- 产物落在 `art/out/{Bg,Cg,Portrait}/<id>.png`（已在 `.gitignore` 里），审图表落在 `art/out/_review/<组>.png`。
- 退出码：0 全部成功 / 2 前置条件不满足（缺 key、缺 node、缺 manifest，并打印配置指引）/ 3 有分组失败。
- 审图通过后再替换占位图（文件名保持不变）：`node story/tools/gen-art.js --generate --used-only --only <组> --out Assets/Resources/Art --force`，然后走第 5 节重建。

**单条命令（底层工具）**：

```
node story/tools/gen-art.js --dry-run                 # 默认：只校验 manifest 并打印统计，不联网不写图
node story/tools/gen-art.js --dry-run --used-only     # 只看剧本引用的 86 条
node story/tools/gen-art.js --generate --used-only --out art/out   # 真实出图（强烈建议先出到 art/out/）
node story/tools/gen-art.js --generate --used-only --only linxiao --out art/out   # 只出某角色/某 kind/某 id
```

**只要审图表**（外部画师交付的 PNG 同样能用它验收）：

```
python story/tools/art-review.py --dir art/out/Bg --out art/out/_review/bg.png --title "场景底图"
python story/tools/art-review.py --dir art/out/Portrait --filter "alice_*" --cols 3 --out art/out/_review/alice.png
```

- 审图表底色是深夜蓝 `(26,30,44)`，透明立绘垫在这上面能直接看出抠边干不干净；每格左下角标资源 id，方便对着 manifest 提返工意见。

**走 DSH 订阅通道（ChatGPT / Grok / Google，不额外付 API 费）**：这条路径由助手逐张驱动 `generate_image`，产物文件名不受我们控制，所以多一步归一化：

1. 设置 → 插件 → 图像生成 → 订阅区，登录任一账号（实测未登录时 `generate_image` 会直接返回「未登录」）。
2. 助手按组出图：bg / cg 用 `aspect_ratio=16:9`，立绘用 `aspect_ratio=2:3`（900x1300 的比例是 0.692，2:3 最接近）。
3. 原始图按 `<id>.png` 放进 `art/out/raw/`，然后归一化到尺寸红线：

   ```
   python story/tools/art-normalize.py --in art/out/raw --out art/out --only bg --report
   ```

   bg/cg 等比放大后中心裁切 1920x1080；立绘四角采样背景色抠底转透明后等比放入 900x1300 透明画布（容差 40、掩码羽化 1，与 gen-art.js 同口径）。manifest 里没有的 id 会列出来并以退出码 3 结束，不静默吞掉。
4. 出审图表给人看（第 3 节的 `art-review.py`），审过再替换占位图，走第 5 节重建。

- **先出到 `art/out/` 人工审图，再替换占位图**：默认输出目录 `Assets/Resources/Art/<Kind>/` 里现在是带白字的占位图，直接生成会因「文件已存在」被跳过（`--force` 会覆盖占位图，慎用）。替换时保持文件名不变。
- 后处理（自动执行）：bg/cg 等比放大后中心裁切为 1920×1080；立绘按四角采样纯色底抠掉转透明，等比放入 900×1300 透明画布；`bg_black` 由本地 Pillow 生成纯色，不耗 API。
- 后处理依赖探测结果（本机 2026-10-15）：**Python 3.12.10 + Pillow 12.3.0 可用；ImageMagick 不可用**（PATH 上的 `convert.exe` 是 Embarcadero Delphi 工具，不是 ImageMagick，工具不会误用）。缺 Pillow 时 `--generate` 会中文报错并退出码 2，绝不静默跳过。
- 失败处理：单张失败重试 3 次（429/5xx 指数退避），最终失败会列清单并以退出码 3 结束，不吞错。

## 4. 命名与尺寸红线

- 文件名 = manifest `id`，路径 = `Assets/Resources/Art/{Bg,Cg,Portrait}/<id>.png`，与 `story/ASSETS.md` 登记表一一对应。
- bg / cg：1920×1080 PNG；立绘：900×1300 透明底 PNG（ASSETS.md 第 15 行的尺寸建议）。
- 画面里**不得出现任何文字/水印**（占位图烙白字就是本轮要消灭的问题）；所有 prompt 的 `negative` 已统一包含「文字，字母，数字，水印，logo，签名…」，外部画师交付同样按此要求验收。
- 既有规则（story/ASSETS.md §6）：**剧本引用了但清单没登记会判不合格**；反之登记了未引用允许（即那 18 条 `used:false` 备用）。改动剧本引用时同步更新 ASSETS.md 与 manifest。

## 6. 「拿到 key 后一次性出 86 张」的现实成本

- 调用次数：85 次 API 调用（86 减 `bg_black` 本地生成）；立绘 31 张中 24 张变体各多带一张参考图，但仍是单次调用。
- 串行 + 限流退避：按每次出图 15–60 秒估算，**约 30–90 分钟**跑完一轮；失败重试另计。
- 费用量级：gpt-image-1 约 $0.02–0.19/张（低/中质量），Gemini 图像预览档按 token 计费同量级——**一轮 86 张大约 $2–16**，返工（表情不对、脸不一致、构图不合格）通常要 2–3 轮，按 3 轮预算更现实。
- 立绘一致性是最大返工源：基准图必须先人工确认再批量出变体（`--only <角色>` 逐角色推进最稳）。
